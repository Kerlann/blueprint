# Story 20.2 — session de vérification manuelle

Ce qui suit ne se teste pas sans fenêtre. Le reste est couvert par les tests ; ce document ne
répète pas ce qu'ils protègent déjà, il liste ce qu'aucun d'eux ne peut voir.

## Mise en place

```
./gradlew runClient
```

Puis en jeu, dans un monde de création :

```
/blueprint create test:fonctions
/blueprint edit test:fonctions
```

## 1. L'onglet et le panneau (AC1, AC8)

| # | Geste | Attendu |
|---|---|---|
| 1.1 | Cliquer l'onglet **Fonctions** | La colonne de gauche montre la liste des fonctions, plus celle des variables |
| 1.2 | Cliquer le « + » de l'en-tête | `fonction1` apparaît, sélectionnée, avec **deux nœuds** dans son corps |
| 1.3 | Un seul `Ctrl+Z` | La fonction disparaît entièrement — pas en trois fois |
| 1.4 | `Ctrl+Y`, puis double-clic sur la ligne | Le canevas montre le corps ; la ligne passe au **vert** |
| 1.5 | Revenir à l'onglet **Graphe** | Le canevas remontre le graphe principal |
| 1.6 | Sélectionner la ligne, cliquer « ✎ », taper un nom, Entrée | Renommée |
| 1.7 | Poser un `Appeler …` dans le graphe, puis renommer la fonction | Le **premier** Entrée avertit du nombre d'appels cassés ; le second applique |

**Ce qu'on regarde vraiment** : que le panneau se manipule comme celui des variables sans
qu'on ait à le réapprendre. Si un geste surprend, c'est un défaut même s'il « marche ».

## 2. Éditer un corps (AC2, AC3, AC11)

| # | Geste | Attendu |
|---|---|---|
| 2.1 | Dans un corps : palette (Espace), poser un nœud, le câbler, le déplacer | Comme dans le graphe principal |
| 2.2 | Minimap, `Ctrl+F`, alignement, copier-coller | Tous opérants sur le corps |
| 2.3 | Un geste dans le corps, un dans le graphe, puis deux `Ctrl+Z` | Ils se défont **dans l'ordre inverse des gestes**, chacun dans son graphe |
| 2.4 | `Ctrl+S` depuis un corps | Enregistre, **et l'on reste dans le corps** |
| 2.5 | Rouvrir l'éditeur | Le corps est là, complet |
| 2.6 | Tenter de poser un commentaire dans un corps | Refusé, avec un message — pas un clic sans effet, pas un commentaire égaré dans le graphe |
| 2.7 | Sélectionner tout dans un corps, Suppr | Les deux bords restent, le reste part |

## 3. La signature (AC4, AC7)

| # | Geste | Attendu |
|---|---|---|
| 3.1 | Dans un corps, cliquer le vide pour tout désélectionner | Le panneau de droite montre **la signature**, pas les métadonnées du blueprint |
| 3.2 | « + Ajouter un paramètre » | `p1` apparaît ; le nœud `func/param` du corps **gagne un pin** |
| 3.3 | Regarder un `Appeler …` posé dans le graphe | Il a gagné le même pin |
| 3.4 | Cliquer le type du paramètre | Il tourne ; les nœuds suivent |
| 3.5 | Câbler le paramètre sur un appel, puis retyper | Le lien reste **et** un diagnostic apparaît — jamais un lien silencieusement faux |
| 3.6 | Cliquer ce diagnostic | La vue se centre sur le nœud fautif |
| 3.7 | Retirer le paramètre (× ) | Même chose : diagnostic, pas de réparation en douce |
| 3.8 | Double-clic sur le nom, renommer en le nom d'un **résultat** | Refusé, le champ se referme |

## 4. La palette (AC6)

| # | Geste | Attendu |
|---|---|---|
| 4.1 | Créer une fonction, **sans fermer l'éditeur** ouvrir la palette | « Appeler *nom* » y est, sous sa propre catégorie, juste après Variables |
| 4.2 | Taper le nom de la fonction | Elle apparaît **en tête** des résultats |
| 4.3 | L'insérer | Le nœud arrive avec **ses pins**, pas un bloc vide |
| 4.4 | Tirer un fil dans le vide, choisir « Appeler … » | Le fil se raccroche à un pin compatible |
| 4.5 | Ouvrir la palette **depuis le corps de `carre`** | « Appeler carre » n'y est pas — la récursion est refusée, la proposer mènerait à un diagnostic |

## 5. Diagnostics et vue script (AC9, AC10)

| # | Geste | Attendu |
|---|---|---|
| 5.1 | Créer une erreur dans un corps (un pin obligatoire non rempli), aller dans l'onglet **Graphe** | Le diagnostic est listé |
| 5.2 | Le cliquer | L'onglet **passe à Fonctions**, le corps s'ouvre, la vue se centre |
| 5.3 | Ouvrir la vue script | Le texte contient `function …` et le contenu du corps |
| 5.4 | Cliquer une ligne du corps | Même chose qu'en 5.2 |
| 5.5 | Copier le script, le réimporter | Le graphe revient identique, fonctions comprises |

## 6. Ce qui doit tourner

| # | Geste | Attendu |
|---|---|---|
| 6.1 | Fermer l'éditeur avec des modifications | La confirmation habituelle |
| 6.2 | `/blueprint enable test:fonctions` puis déclencher l'événement | La fonction s'exécute |
| 6.3 | Sur un **serveur dédié** : éditer, `Ctrl+S` | Le blueprint arrive côté serveur avec ses fonctions |

## Limites connues, à ne pas signaler comme défauts

- **Un corps ne porte pas de commentaires** — `BlueprintFunction` ne stocke que des nœuds et
  des liens. Le geste est refusé, pas silencieusement dévié.
- **`Ctrl+Shift+A` (mise en page automatique) ne range pas un corps.** `AutoLayout` lit le
  graphe principal ; lui apprendre à lire un corps est un travail à part.
- **Le panneau des variables n'est pas visible dans l'onglet Fonctions** — les deux occupent
  la même colonne. Les variables restent atteignables par la palette.
- **Pas de vue « qui appelle cette fonction »**, pas de glisser-déposer depuis le panneau,
  pas d'extraction automatique. Ce sont les limites assumées de la story.
