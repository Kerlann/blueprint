# Story 1.4 : Sérialisation NBT

## Status

Ready for Review

## Story

**En tant que** développeur du mod,
**je veux** sérialiser et désérialiser un blueprint complet en NBT versionné,
**afin que** les blueprints survivent à la sauvegarde du monde, aux mises à jour du mod, et au retrait temporaire d'un mod tiers — sans jamais perdre de données.

## Acceptance Criteria

1. Encodage/décodage NBT pour blueprint, nœud, lien, variable, commentaire, métadonnées, et valeur littérale de chaque type de base.
2. Le NBT racine porte un numéro de version de schéma et une table de migrations extensible (`v(n) → v(n+1)` appliquées en chaîne) ; une migration factice est testée.
3. Round-trip identique (`contentEquals`) sur un graphe de test de **200 nœuds** mêlant types, liens, littéraux, variables et commentaires.
4. Un identifiant de **nœud** inconnu est conservé tel quel (FR40) ; un **type de pin** inconnu (littéral ou variable d'un mod retiré) est préservé en NBT brut et restauré à l'identique quand le mod revient — re-round-trip testé dans les deux états.
5. La taille compressée (gzip) du graphe de 200 nœuds est mesurée et consignée par le test, avec un seuil aligné sur NFR5 (< 1 Mo pour 1 000 nœuds → seuil test : < 200 Ko).
6. **SER-001 (QA 1.2)** : les types paramétrés sont encodés **structurellement** — `list<int>` et `list<string>` se distinguent au décodage ; imbrication testée (`map<string, list<int>>`).
7. **GHOST-001 (QA 1.3)** : un lien exec entre deux nœuds fantômes ne produit plus de faux `DATA_CYCLE` (liens fantôme↔fantôme exclus de la détection de cycle) ; test dédié.
8. Nettoyage DOC-002 : les helpers morts `NodeShape.PinDef.in()`/`required()` sont supprimés.

- **Test de préservation le plus fort du projet** : la re-sauvegarde SANS le mod produit
  des octets NBT **identiques** à la sauvegarde d'origine (`assertEquals(saved, resaved)`) —
  pas seulement « rien ne casse », mais « rien ne dérive », même après N cycles.
- Encodage hand-rolled sur `CompoundTag` plutôt que DFU `Codec` composé : la préservation
  d'entrées irrésolubles et l'encodage structurel des types se seraient mal exprimés en
  DFU ; les valeurs de littéraux passent, elles, par les `Codec` des types (NbtOps).

  leurs migrations factices sans polluer d'état statique.
- Ajout api : `PinType.genericName()` (le nom du slot était enfermé dans `GenericPinType`,
  package-private) — nécessaire à l'encodage, utile au futur `NodeDescriptor` (2.4).
- `decode` ignore silencieusement les entrées corrompues (UUID/id invalides) : le rapport
  de chargement agrégé arrive avec `BlueprintStorage` (story 6.1), qui saura les compter.
- `revision` persistée : une session d'édition reprend avec un verrouillage optimiste cohérent.

### Code Quality Assessment

Story exemplaire. Le test de préservation à l'octet près (`assertEquals(saved, resaved)`
sans le mod) est la garantie la plus forte livrée jusqu'ici : non seulement rien ne
casse, mais rien ne dérive, quel que soit le nombre de cycles sauvegarde/rechargement
sans le mod tiers. Le réflexe « javap avant d'écrire » institué après la 1.2 a payé —
compilation et tests verts au premier passage sur une API NBT pourtant refondue en
1.21.5. Le choix hand-rolled vs DFU est bien argumenté (la préservation d'entrées
irrésolubles s'exprime mal en Codec composé) et les valeurs passent, elles, par les
codecs officiels des types.
