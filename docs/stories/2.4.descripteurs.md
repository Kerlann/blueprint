# Story 2.4 : Descripteurs de nœuds sérialisables

## Status

Ready for Review

## Story

**En tant que** joueur sans les mods du serveur,
**je veux** que l'éditeur affiche tous les nœuds du serveur depuis de purs descripteurs,
**afin de** voir et câbler des nœuds dont je n'ai pas le code (FR35, principe P1).

## Acceptance Criteria

1. `NodeDescriptor` = identifiant, catégorie, clés de traduction, pins (nom, nature, type **structurel**, défaut), pure, permission, fuelCost, deterministic — et **aucune référence** à `NodeAction` ni à une classe du mod fournisseur (AC4 du PRD).
2. Encodage/décodage en round-trip testé : NBT (payload) + passage réseau (`ByteBufCodecs`/`FriendlyByteBuf`) sur les 3 nœuds réels du testmod, valeurs par défaut incluses.
3. Un **hash stable** de l'ensemble du registre est calculable : indépendant de l'ordre d'enregistrement, identique entre deux chargements identiques, différent au moindre changement (base de la synchro FR35 : « hash égal → pas de renvoi »).
4. Le décodage résout les types via un résolveur injecté (le futur registre synchronisé du client) ; un type irrésoluble fait échouer le descripteur proprement (null), pas silencieusement.
5. Écart assumé vs source-tree : `NodeDescriptor` vit dans `core/registry` (il réutilise `PinTypeNbt` de `core/graph`), pas dans `api` — les mods tiers ne consomment pas les descripteurs, seuls `core` et `client` le font ; `source-tree.md` mis à jour.

## Tasks / Subtasks

- [x] `NodeDescriptor` : record + `PinDescriptor` + `of(NodeType)` + `encode()`/`decode(tag, resolver)` + `canonical()` — décodage tout-ou-rien (type/kind/permission irrésolubles → null)
- [x] `RegistryHash` : SHA-256 des formes canoniques triées, séparateur nul entre entrées

- [x] `NodeDescriptorTest` : 5 tests — projection sans action, round-trips NBT **et** réseau (`ByteBufCodecs.TRUSTED_COMPOUND_TAG`, vérifié au javap) sur les 3 nœuds réels, **identité des types préservée au décodage** (`assertSame`), irrésoluble → null, hash stable/indépendant de l'ordre/sensible au changement

## Dev Notes

- Le type structurel réutilise `PinTypeNbt` (SER-001) — `list<int>` ≠ `list<string>`
  aussi dans les descripteurs.
- Hash : PAS de `CompoundTag.toString()` (ordre de HashMap non garanti entre versions) —
  forme canonique construite champ par champ dans l'ordre déclaré, descripteurs triés par id.
- Réseau : `ByteBufCodecs.TRUSTED_COMPOUND_TAG` si présent (javap), sinon `writeNbt/readNbt`.
- La synchro réelle (paquets, fragmentation, login) = story 6.2 ; ici on livre la forme et le hash.
