# Story 5.6a : Annuler / Rétablir

## Status

Done

## Story

**En tant que** joueur,
**je veux** `Ctrl+Z` / `Ctrl+Y` sur toutes mes actions d'édition,
**afin de** ne jamais perdre de travail (principe U2 : jamais de perte silencieuse) —
les inverses sont déjà collectés par `CanvasController` depuis la 5.2a, il manque la
pile qui les rejoue.

## Acceptance Criteria

1. `client/editor/history/UndoStack.java` : pile d'entrées réversibles, **≥ 50
   niveaux**, couvrant TOUTES les mutations (déplacement, suppression, câblage,
   détachement, insertion palette, littéraux, et toute mutation future). (AC1 PRD 5.6)
2. **Coalescence par geste** : un glisser de 40 images = 40 `MoveNode` = UNE entrée
   d'annulation (bornée presse→relâche) ; une insertion avec auto-connexion
   (`AddNode`+`AddLink`) = une entrée ; une suppression multiple = une entrée.
3. `Ctrl+Z` annule (applique les inverses en ordre inverse), `Ctrl+Y` ou
   `Ctrl+Shift+Z` rétablit ; une nouvelle action purge la branche « redo ». Annuler
   pendant un geste en cours termine d'abord le geste.
4. Le rejeu passe par `EditOperation.apply` (l'inverse d'un inverse est fourni par
   `Result.inverse()` — c'est ce qui alimente le redo) ; jamais de mutation directe.
5. Pure et testée headless : scénarios déplacement coalescé, suppression+restauration
   (liens compris), purge du redo, plafond de 50, geste interrompu.

## Dev Notes

- `Result.ok(inverse)` : rejouer un inverse retourne l'inverse-de-l'inverse — le
  redo est gratuit, il suffit de conserver ce que `apply` rend au moment du undo.
- La 5.2b/5.5/5.8 créeront leurs entrées via le même chemin `applyTracked` : la
  couverture « toutes les mutations » tient tant que personne ne contourne
  `CanvasController.apply`.
- Priorité de la story : AVANT les grosses features d'édition (5.5, 5.8) pour que
  chaque nouvelle mutation naisse annulable.
