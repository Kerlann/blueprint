# Story 5.2c : Sélecteurs riches — item, bloc, position

## Status

Done

## Story

**En tant que** joueur,
**je veux** choisir un item ou un bloc dans un sélecteur visuel avec aperçu, et
capturer une position d'un clic (« position du joueur »),
**afin de** remplir les littéraux que la 5.2b ne sait saisir qu'en texte — les types
qui font le lien avec le contenu réel du jeu.

## Acceptance Criteria

1. Pin `itemstack` : la zone littérale montre l'**icône réelle** de l'item (rendu
   `GuiGraphics.renderItem`) ; cliquer ouvre un **sélecteur** : recherche (réutilise
   la mécanique `NodeSearch`), grille d'icônes depuis `BuiltInRegistries.ITEM`,
   clic = `SetLiteral`. (UX §4)
2. Pin `blockstate` : même sélecteur restreint aux blocs ; les propriétés d'état
   (facing, etc.) restent en v1.1 — le bloc par défaut suffit (consigné).
3. Pins `vec3` / `blockpos` : trois champs numériques (5.2b) + bouton **« position
   du joueur »** qui capture la position courante côté client. (UX §4)
4. `direction` : passe du champ 5.2b à une énumération visuelle (6 boutons N/S/E/O/
   Haut/Bas).
5. Le sélecteur est un popup modal du canevas (même exclusivité que la palette) ;
   recherche par nom traduit d'item ; performances : ouverture < 100 ms avec tout
   le registre vanilla (~1 500 items).
6. Ce qui est testable headless l'est (état du sélecteur, filtrage, capture de
   position mockée) ; le rendu d'icônes est un VERIFY en jeu.
