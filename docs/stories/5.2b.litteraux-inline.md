# Story 5.2b : Littéraux inline — éditer les valeurs sur le nœud

## Status

Draft

## Story

**En tant que** joueur,
**je veux** modifier une valeur directement sur le nœud (nombre, texte, booléen,
énumération, identifiant) comme dans Unreal Engine,
**afin de** paramétrer mon graphe sans quitter le canevas — aujourd'hui les littéraux
existent dans le modèle (`SetLiteral`) mais sont invisibles et inéditables.

## Acceptance Criteria

1. Un pin d'entrée **data non câblé** affiche sa valeur littérale courante (ou son
   défaut) à droite du nom, selon le type : `bool` case à cocher, `int`/`long`/`double`
   champ numérique (molette = ±1, Shift+molette = ±10), `string`/`text` champ texte,
   `resourcelocation` champ texte avec validation `Identifier`, `direction`
   énumération déroulante. Un pin câblé masque son littéral (le lien prime). (AC3 PRD 5.2)
2. Cliquer la zone littérale ouvre le **contrôle d'édition en place** ; `Entrée`
   valide → `EditOperation.SetLiteral` (inverse collecté), `Échap` annule sans
   toucher au modèle. Un seul contrôle actif à la fois ; clic ailleurs valide.
3. Saisie invalide (nombre malformé, identifiant invalide) : le champ passe en rouge
   et **rien n'est appliqué** — jamais de littéral corrompu dans le graphe
   (`SetLiteral` revalide de toute façon : type + `Literals.matches`).
4. Le clavier de l'éditeur est suspendu pendant l'édition (pas de `Suppr` qui efface
   un nœud en pleine frappe) ; la palette et l'édition sont mutuellement exclusives.
5. La logique (état d'édition, validation par type, commit/annulation) est **pure et
   testée headless** (`LiteralEditState`) ; le rendu des contrôles reste dans
   `NodeWidget`/`CanvasWidget`.
6. Types différés explicitement : `itemstack`/`blockstate` (sélecteur d'item avec
   aperçu — story 5.2c dédiée), `vec3`/`blockpos` (bouton « position du joueur »,
   même story). Le champ affiche « … » non éditable pour ces types en attendant.

## Dev Notes

- `EditOperation.SetLiteral(uuid, pin, valeur)` existe et revalide
  (`def.type().isAssignableFrom(value.type()) && Literals.matches(value)`) — le
  client peut donc tenter et afficher le refus, mais valider en amont donne le
  feedback rouge sans aller-retour.
- `LiteralValue.of(PinTypes.X, valeur)` pour construire ; les défauts viennent de
  `NodeDescriptor.PinDescriptor.defaultValue()`.
- Molette sur champ numérique : `mouseScrolled` doit tester l'édition active AVANT
  le zoom caméra.
- La démo (`flow/wait.ticks`, `player/send_message.text`) devient réellement
  éditable — c'est le test manuel : changer le message de bienvenue en jeu.
