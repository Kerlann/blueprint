# Stories 7.3 + 7.4 + 7.5 : Nœuds monde, entité/joueur, item/texte

## Status

Done

## Story

**En tant que** joueur,
**je veux** des nœuds qui touchent le monde (blocs, sons, météo, spawns), les entités
(téléportation, santé, effets) et les items/textes,
**afin que** mes blueprints fassent des choses VISIBLES en jeu — c'est la matière
première du produit.

> Découpage assumé : les actions manipulent `ServerLevel` — invérifiables headless.
> Le testable headless l'est (formes, permissions, pureté, symétrie des clés de
> langue, actions texte pures via un contexte stub) ; le comportement en monde est
> VERIFY-7.3/7.4/7.5 (session finale) puis gametest (spike 1.6).

## Acceptance Criteria

1. **7.3 Monde** (10) : `world/get_block`, `set_block`, `is_block`, `spawn_entity`,
   `play_sound`, `particles`, `set_weather`, `set_time`, `explosion`, `drop_item` —
   chaque nœud déclare sa permission (lectures GAMEPLAY, mutations WORLD,
   `explosion` ADMIN) ; les lectures du monde sont des nœuds EXEC (jamais purs :
   la mémoïsation des purs rendrait la lecture incohérente dans une exécution).
2. **7.4 Entité/joueur** (9) : `entity/position`, `teleport`, `health`,
   `set_health`, `heal`, `add_effect` ; `player/give_item`, `title`, `give_xp`,
   `set_gamemode` (ADMIN) — sécurité systématique : entité invalide/retirée ou
   non-vivante → `ctx.fail` traduit, jamais d'exception (AC PRD).
3. **7.5 Item/texte** (7) : `item/create`, `count`, `with_count`, `matches` ;
   `text/literal`, `colored`, `concat` — purs et déterministes (les seules
   constructions, pas de lecture du monde).
4. Identifiants inconnus au runtime (son, particule, effet, entité, item, couleur)
   → `ctx.fail` traduit nommant l'identifiant ; particule complexe (dust…) refusée
   proprement.
5. Clés de langue en/fr pour TOUS les nœuds — un test verrouille la symétrie
   (chaque nœud enregistré a sa clé `.name` dans les deux fichiers).
6. Formes/permissions/pureté testées headless ; actions texte testées via contexte
   stub ; build vert.
