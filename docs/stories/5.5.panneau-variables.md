# Story 5.5 : Panneau des variables et nœuds Get/Set

## Status

Done

## Story

**En tant que** joueur,
**je veux** créer et gérer des variables typées dans un panneau latéral et les glisser
dans le canevas en nœuds Get/Set, comme dans Unreal,
**afin de** faire circuler de l'état dans mes graphes — le modèle (`Variable`,
`VarScope`) et la VM (instructions lecture/écriture) existent, il manque l'interface
ET les nœuds.

## Acceptance Criteria

1. **Panneau gauche repliable (`Tab`)** listant les variables par portée (UX §2, §7),
   pastille de couleur du type : `+` crée (nom unique, type choisi, portée),
   double-clic renomme, menu contextuel retype / change la portée / supprime /
   fixe la valeur par défaut (contrôles de la 5.2b réutilisés). (AC1 PRD 5.5)
2. Toutes les mutations passent par les `EditOperation` de variables existantes
   (ou ajoutées si manquantes — vérifier les 16 ops), inverses dans l'`UndoStack`.
3. **Glisser une variable dans le canevas crée un nœud `Get`** ; **Ctrl+glisser crée
   `Set`** (exec in/out + entrée valeur). (AC2 PRD 5.5)
4. **Nœuds Get/Set réels** : `blueprint:var/get` et `blueprint:var/set` paramétrés
   par le nom de variable (littéral `string` figé), sorties/entrées typées par la
   variable ; le compilateur les traduit vers les instructions variable existantes.
   Un graphe Get/Set s'exécute headless de bout en bout (test VM).
5. **Retypage incompatible** : confirmation listant les liens qui seront invalidés
   avant d'appliquer, annulable (FR10, U2). (AC3 PRD 5.5)
6. Variable non utilisée : point discret dans le panneau, pas d'avertissement (UX §7).

### Completion Notes List

- **Décision d'architecture consignée** : `var/get`/`var/set` sont des `NodeType`
  réels (palette, rendu, validation) mais **jamais des `Call`** — le compilateur les
  abaisse en `LoadVar`/`StoreVar` (`VarNodes` porte les constantes partagées
  validateur/compilateur/éditeur). Leurs actions jettent : les atteindre = bogue.
- Le validateur exige un pin `var` **littéral** (pas câblé — le nom se résout à la
  compilation) nommant une variable existante → `VARIABLE_NOT_FOUND` ciblé nœud.
- `var/set` en fin de fil émet `Return` ; successeur déjà émis → `Jmp` (arête arrière).
- Renommer une variable **repointe les nœuds liés** dans le même geste — sinon ils
  mourraient en `VARIABLE_NOT_FOUND` silencieux.
- Retypage : cycle T sur la ligne sélectionnée ; les liens cassés sont comptés par
  assignabilité réelle (les pins var sont `any`, `canLink` ne peut pas trancher) —
  premier clic avertit, second applique (déviation : pas de modal avec aperçu, le
  panneau affiche l'avertissement ; à raffiner en 5.10).
- Panneau : `Tab` replie, `+` crée `varN` (double/GRAPH), double-clic renomme,
  glisser vers le canevas dépose `Get` (`Ctrl` = `Set`) accroché.
- Restes consignés : valeur par défaut éditable (5.10), ascenseur du panneau,
  typage fin des pins var par instance (résolution jokers par variable), point
  « variable inutilisée » (AC6 — non fait, avec l'ascenseur).
- VERIFY-5.5 (drag, rendu panneau) rejoint la session en jeu finale.
