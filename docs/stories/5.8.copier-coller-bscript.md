# Story 5.8 : Copier / couper / coller / dupliquer via BScript

## Status

Ready for Review

## Story

**En tant que** joueur,
**je veux** `Ctrl+C/X/V` et `Ctrl+D` sur ma sélection, avec un presse-papier qui est
du **texte BScript**,
**afin de** réutiliser des morceaux de graphe — et de les partager : coller dans
Discord un bout de blueprint lisible, c'est le principe U6 (« le texte est une porte
de sortie »). L'épic 4 (générateur + parseur) est complet : cette story est le pont
éditeur↔BScript.

## Acceptance Criteria

1. **`Ctrl+C`** sérialise la sélection en BScript dans le presse-papier **système**
   (partageable hors du jeu) : sous-graphe = nœuds sélectionnés + liens internes +
   littéraux + variables référencées (déclarées en tête). `Ctrl+X` = copie puis
   suppression (une entrée d'annulation).
2. **`Ctrl+V`** parse le presse-papier (`ScriptParser`) : succès → insertion au
   curseur avec **UUID neufs**, positions décalées en bloc (le coin haut-gauche du
   fragment sous le curseur, accroché), la nouvelle sélection = les nœuds collés ;
   échec de parse → message d'état, rien n'est inséré. Coller deux fois = deux
   copies indépendantes.
3. **`Ctrl+D`** duplique la sélection décalée de +16/+16 sans passer par le
   presse-papier système.
4. Variables référencées absentes du blueprint cible : créées si déclarées dans le
   fragment, sinon le nœud Get/Set colle en **fautif** (liseré 5.6b) — jamais de
   refus silencieux du collage.
5. Round-trip testé headless : sélection → copie → collage = graphes équivalents à
   translation et UUID près ; collage d'un texte invalide = état inchangé ;
   duplication = une entrée d'annulation.

### Completion Notes List

- **Découverte structurante** : `ScriptGenerator` n'émet que des blocs `on <event>` —
  une chaîne exec sans événement disparaît du texte. Solution SANS toucher `core` :
  `extract` greffe un événement `signal` **synthétique** à la position sentinelle
  (−1 000 000) en tête de chaque chaîne orpheline ; `@pos` survit au round-trip et
  sert de marqueur ; `paste` retire ces nœuds après parse. Le presse-papier reste du
  BScript 100 % standard, collable dans /blueprint import.
- Décision inversée vs draft : l'extraction vit dans `client/editor/ClipboardCodec`
  (fragment construit aux `EditOperation` sur un Blueprint neuf), pas dans
  `core/script` — aucun conflit avec la session BScript, et 9.x pourra la déplacer.
- **Limitation consignée** : un nœud PUR sans consommateur dans la sélection est
  inliné/perdu par le générateur (copier un `math/add` seul ne survit pas) — à lever
  si le générateur apprend les purs orphelins (4.2b ?).
- `pasteFragment` : variables du fragment créées si absentes, UUID remappés,
  positions décalées en bloc (coin haut-gauche accroché sous le curseur), liens aux
  extrémités non remappées abandonnés, sélection = nœuds collés, un geste d'annulation
  (testé : undo vide tout, redo + second collage = deux copies indépendantes).
- `Ctrl+D` duplique via le même moteur (fragment direct, +16/+16, sans presse-papier).
- VERIFY-5.8 (presse-papier système réel) rejoint la session en jeu finale.
