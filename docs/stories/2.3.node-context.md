# Story 2.3 : Contexte d'exécution des nœuds

## Status

Ready for Review

## Story

**En tant que** développeuse de mod,
**je veux** un `NodeContext` concret pour lire mes entrées, écrire mes sorties et piloter le flux,
**afin que** mes actions s'exécutent en sécurité — et que toute erreur de ma part me soit signalée clairement, jamais silencieusement.

## Acceptance Criteria

1. `ctx.in(name)` typé, `ctx.out(name, value)`, `ctx.server()`, `ctx.level()`, `ctx.blueprint()` (via `BlueprintHandle` api), `ctx.trigger()` (via `TriggerContext` placeholder, complété en 2.5).
2. Lire un pin inexistant, lire/écrire une valeur du mauvais type Java, ou écrire sur un pin inconnu → exception de développement immédiate nommant le nœud et le pin.
3. `ctx.exec(pin)` choisit la branche exec de sortie (dernier appel gagnant, documenté) ; pin exec inexistant → exception.
4. `ctx.suspend(ticks)` (≥ 1) enregistre la demande de suspension, consommable par la future VM ; `ctx.fail(Component)` enregistre une mise en faute propre.
5. **Garde anti-fuite** : le contexte est invalidé après l'appel de l'action — toute méthode appelée ensuite lève, testé (AC5 du PRD).
6. Les 3 nœuds du testmod s'exécutent réellement à travers le contexte (echo, doublement, branchement pair/impair) — première exécution de bout en bout du projet.

## Dev Notes

- La capture d'exception d'action → `FAULTED` est le travail de la VM (3.3) ; ici
  l'exception traverse `invoke` telle quelle, mais le contexte est invalidé même en cas de levée.
- `server()`/`level()` lèvent si absents du contexte (nœud pur évalué hors monde) —
  headless-safe : les tests n'en fournissent pas.
- Emplacement `core/vm/` [Source: source-tree] ; les types api ajoutés sont consommés,
  jamais implémentés par les tiers (ajout non cassant).

chemin nominal ET sur exception, avec un scénario de fuite volontaire — exactement ce que

3.3. Un low : `in()` retourne null quand ni valeur ni défaut n'existent — NPE opaque
possible dans une action tierce sur un graphe fantôme ; à trancher en 3.3 (CTX-001, avec
`outputs()` à rendre non modifiable au passage).
