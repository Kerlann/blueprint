# Story 5.3 : Liens — rendu et câblage

## Status

Done

## Story

**En tant que** joueur,
**je veux** voir les liens du graphe en courbes colorées et pouvoir câbler ou décâbler
des pins à la souris,
**afin que** le graphe se lise et se construise — le reproche « on dirait que c'est
vide » vient de là : les liens existaient dans le modèle sans être dessinés.

## Acceptance Criteria

1. Les liens se rendent en **courbes de Bézier** à tangentes horizontales, colorées
   par le type du pin source, **exec plus épais** (3 px contre 2) ; segments tracés
   par rectangles pivotés via la pose 2D. Les liens dont les deux extrémités sont
   hors champ ne sont pas calculés (culling). (AC1 PRD)
2. **Tracé par glisser** : presser un pin démarre un lien ; l'aperçu suit le curseur ;
   relâcher sur un pin compatible applique `EditOperation.AddLink` —
   `GraphValidator.canLink` reste **la** source de vérité (cardinalité, types,
   direction) : aucun doublon de règles côté client. (AC1)
3. Pendant le glisser, les pins **incompatibles passent à ~30 % d'opacité** ; la
   compatibilité est évaluée par `canLink` sur un lien hypothétique. (AC2)
4. **Alt+clic** sur un pin câblé détache son ou ses liens (`RemoveLink`, inverses
   collectés). (AC4 — le re-câblage Ctrl+glisser est noté pour plus tard)
5. **Relâcher dans le vide** ouvre la palette filtrée par le type transporté (livrée
   par la 5.4a) et le nœud choisi se connecte automatiquement. (AC3, FR29)
6. Logique pure testée headless : hit-test de pin, cycle presse→glisse→relâche,
   refus de lien invalide, détachement, compatibilité.
