# Story 5.1 : Canevas de l'éditeur

## Status

Ready for Review

## Story

**En tant que** joueur,
**je veux** un écran d'éditeur avec un canevas navigable (pan, zoom, grille) qui ne
dessine que ce qui est visible,
**afin que** la base de l'éditeur visuel soit posée et reste fluide même sur un grand
graphe (NFR1), avant d'y construire les nœuds (5.2) et les liens (5.3).

> Périmètre assumé : le canevas affiche les nœuds en **boîtes de niveau de détail**
> (rectangle teinté + titre) — le rendu complet depuis le descripteur (pins, littéraux,
> catégories) est la story 5.2. L'ouverture se fait par un **raccourci clavier de dev**
> sur le blueprint de démo ; l'ouverture réelle depuis le serveur (synchro registre,
> patchs) est l'épic 6.

## Acceptance Criteria

1. `BlueprintEditorScreen` s'ouvre (raccourci dev) et le canevas se déplace au **clic
   milieu glissé** et à **Espace + clic gauche glissé** ; zoom **molette** de 0,25× à
   2,00× en 8 crans, centré sur le curseur (le point du monde sous la souris ne bouge
   pas), `Ctrl +/−` zoome aussi. `F` recentre sur l'ensemble du graphe. (AC1 PRD + UX §3)
2. Grille au pas de 16 px monde, lignes majeures toutes les 4, **atténuée sous 0,5×**
   de zoom ; accroche optionnelle basculée par `Ctrl+G` (l'état est exposé pour 5.2,
   `Camera.snap` arrondit déjà une position monde). Rendu correct à tous les crans de
   zoom : pas de lignes manquantes ni dédoublées aux bords. (AC2)
3. **Culling avant tout calcul** : seuls les nœuds dont la boîte intersecte le rectangle
   visible sont transformés et dessinés (coding-standards §5) ; niveau de détail : sous
   0,5× boîte + titre seul, sous 0,35× boîte sans titre. (AC3, UX §3)
4. **Banc de rendu headless** dans `client` : 500 nœuds, la passe CPU par image
   (culling + transformations + construction de la liste de dessin) reste sous **2 ms**
   en moyenne sur 1 000 images (budget 16,6 ms à 60 fps, le GPU n'étant pas mesurable
   sans jeu) ; le banc échoue le build s'il dépasse. La mesure en jeu (F3, 500 nœuds)
   est consignée comme VERIFY-5.1 pour la prochaine session en jeu. (AC4, NFR1)
5. La caméra est de la **logique pure testée** (monde↔écran, crans de zoom bornés,
   zoom sur pivot, accroche, rectangle visible) — tests JUnit sans Minecraft, comme
   `core` (coding-standards §7).
6. Chaînes visibles via `Component.translatable`, clés `en_us` + `fr_fr` (titre
   d'écran, nom et catégorie du raccourci).

## Dev Notes

- **Mappings Mojang 1.21.11** : `GuiGraphics` (pas `DrawContext`), `Screen`,
  `Component.translatable`, `Identifier`. En cas de doute, `javap` sur le JAR mergé
  (tech-stack.md).
- **Pas d'exécution de graphe côté client** (coding-standards §1.3) : le canevas lit le
  modèle (`Blueprint`, `Node.position()`, `NodeShape`) et n'appelle jamais compilateur
  ni VM. L'usage direct du modèle `core` est un raccord MVP ; les descripteurs
  synchronisés arrivent avec l'épic 6.
- **Pas de `stream()` dans le rendu** (coding-standards §5) : boucles indexées,
  tampons réutilisés (`ArrayList` de travail conservée entre les images).
- Crans de zoom : progression quasi géométrique arrondie
  `0.25, 0.35, 0.50, 0.70, 1.00, 1.25, 1.60, 2.00` — 8 valeurs, extrêmes exigés par le
  PRD exacts (0,25 et 2,00), passant par 1,00 (cran par défaut) et par 0,50 (le seuil
  d'atténuation de la grille tombe pile sur un cran).
- Zoom sur pivot : `world(pivot)` avant = après → `origin' = pivot/zoom' - (pivot/zoom - origin)`.
- La grille se dessine en coordonnées écran à partir du premier multiple visible du pas
  monde (`Math.floor(left/pas)*pas`) : c'est ce qui évite lignes manquantes/dédoublées.
- Le thème JSON (`assets/blueprint/theme/default.json`) est la story 5.7 : couleurs en
  constantes locales pour l'instant, reprises des valeurs de la spec UX §12.
- Les nœuds n'ont pas de taille persistée : `NodeGeometry` la dérive de la forme
  (`titleHeight 18 + 12·max(pins in, pins out)`, largeur 140) — suffisant pour le
  culling et les boîtes LOD ; 5.2 raffinera avec les littéraux inline.
- Le banc mesure la **passe CPU** uniquement : culling + transformations + liste de
  dessin, sans GL. Seuil 2 ms volontairement large (machine CI inconnue) mais 8× sous
  le budget d'image ; la vraie mesure fps est un VERIFY en jeu.
- Fichier `fabric.mod.json` : vérifier que l'entrypoint `client` pointe déjà
  `fr.blueprint.client.BlueprintClient` (JAR unique, ressources dans `core`).
- **Collision de branches** : une autre session travaille sur `core/nodes` et
  `core/command` ; cette story ne touche côté `core` que les deux fichiers `lang/*.json`
  (ajouts de lignes, conflit trivial au merge).

### Testing

### Completion Notes List

- **APIs 1.21.11 vérifiées au `javap` sur le JAR mergé** (procédure tech-stack) avant
  d'écrire une ligne : `GuiGraphics.pose()` retourne désormais un
  `org.joml.Matrix3x2fStack` (pile 2D — `pushMatrix`/`translate`/`scale`), les entrées
  passent par les records `KeyEvent`/`MouseButtonEvent` (`mouseClicked(MouseButtonEvent,
  boolean)`, `keyPressed(KeyEvent)`, modificateurs via `hasControlDown()` du record), et
  les catégories de raccourcis par `KeyMapping.Category.register(Identifier)` (clé de
  langue dérivée : `key.category.blueprint.main`).
- `Camera` et `NodeGeometry` sont 100 % pures (seul import : `Vec2d`/modèle core) —
  c'est ce qui rend le banc headless honnête : il exécute exactement le code de la
  passe de rendu (culling → transformation → liste de dessin), pas une copie.
- Le titre en LOD est mis à l'échelle par la pose 2D et découpé au scissor du nœud ;
  sous 0,35× plus aucun texte (UX §3), la clé suit le motif
  `blueprint.node.<ns>.<path>.name` (chemin avec `/` littéral, comme les lang existants).
- Le recadrage `F`/ouverture choisit le plus grand cran contenant la boîte englobante
  avec 40 px de marge ; à la réouverture après redimensionnement, la position de
  travail est conservée (recadrage à la première ouverture seulement).
- Banc : seuil 2 ms très conservateur — la passe réelle mesurée est de l'ordre de la
  dizaine de microsecondes pour 500 nœuds (500 tests AABB + ~20 transformations).
- Restes explicites : VERIFY-5.1 (fps en jeu au F3, graphe 500 nœuds — le banc ne
  mesure pas le GPU) ; le rendu complet des nœuds (pins, littéraux, catégories) est
  la 5.2 ; le thème JSON rechargeable est la 5.7 (couleurs UX §12 en constantes).
