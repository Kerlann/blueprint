# Story 2.2 : Registre de nœuds et entrypoint

## Status

Done

## Story

**En tant que** développeuse de mod tiers,
**je veux** enregistrer mes nœuds via l'entrypoint Fabric `blueprint`,
**afin que** mon intégration ne dépende d'aucune classe interne et survive aux mises à jour de Blueprint.

## Acceptance Criteria

1. `BlueprintPlugin` expose `registerNodes(NodeRegistry)` (obligatoire), `registerTypes(PinTypeRegistry)` et `registerEvents(EventRegistry)` (défaut vides) ; ordre d'appel : types → nœuds → événements, tous plugins confondus par phase.
2. Les registres sont figés après la phase d'enregistrement ; toute écriture ultérieure lève une exception.
3. Un plugin qui lève une exception est isolé : journalisé avec le nom du mod, ses enregistrements partiels retirés (ses nœuds deviendront fantômes), les autres plugins chargent normalement, jamais de crash au démarrage.
4. Un doublon d'identifiant est refusé avec un message nommant les deux mods ; un namespace ne correspondant pas au modid du fournisseur produit un avertissement journalisé (convention, pas blocage).
5. Le `testmod` enregistre **3 nœuds réels** via l'entrypoint, et un test (core, headless — le testmod est ajouté au classpath de test) vérifie leur présence et leurs pins après chargement par le `PluginLoader`. Vérification en jeu : session manuelle/1.6.
6. `NodeRegistryImpl` implémente `NodeTypeLookup` : les nœuds enregistrés alimentent directement le `GraphValidator` (adaptateur `NodeType` → `NodeShape`, `required` = entrée DATA sans défaut de pin ni de type).
